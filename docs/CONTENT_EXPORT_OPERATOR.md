# Reviewed curriculum export from the owner workspace
Active release history shows a download-request action only for curriculum:publish. The JSON contains exactly format, draft ID and release ID; no draft body, admin credentials, private key or signature. It is an unsigned reference, not authorization. Keep production signing secrets outside Git and Vercel. On an independently trusted operator machine with the dedicated admin database and encryption key provided privately, use python admin-src/export_request.py request.json --key-file /private/path/signing.pem --key-id REVIEWED_ID --output signed.json. This checks exact request shape, dedicated verified-TLS DB, pinned public key match, fresh MFA and publish permission, expected active reviewed release and durable sequence through the existing transactional exporter. Interactive login revokes earlier admin sessions. New output is exclusive and mode 0600 on POSIX; a failed write may consume a sequence, which is safe but must not be reused. Never publish a request itself. The separate dynamic catalog candidate accepts only verified signed envelopes and an explicit publication confirmation. There is deliberately no hosted signing or browser-supplied content signing. No real keys, accounts, files or database changes performed; disposable tests only.
