# Staging CMS review and release history
Draft -> Review -> Approved -> Published (admin-local staging only). Revision increases for each transition. Only draft state can be edited. Review requires a different account from the last editor, explicit server permission; publish requires approved state and publication permission. Submit/approve/publish and rollback revalidate with the current trusted activity engine. Each staged release is inserted as a separate versioned snapshot; API does not modify/delete releases. A locked active pointer can be switched back to an earlier compatible release with expected-active conflict checking, without deleting newer versions or changing the editable draft. Reopening a published draft starts another edit/review cycle. Audit records actions. No public student delivery, deployed-client capability checks, content signing, or production deployment. Database tests cover permissions, state transitions, revision conflicts and rollback. Browser test for preceding visual editor was failing on select accessibility locator; explicit aria-label added and rerun required.
