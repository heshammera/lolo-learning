# Offline-first web and Android (candidate)
Android previously loaded the Vercel URL as its entire UI. The new build packages only the public app shell, curriculum and branding into www-bundled and uses Capacitor's local HTTPS asset server. The configured hostname is the previous production hostname to preserve the WebView storage origin where Android retains application data. Verify upgrade preservation on a real device with the same signing certificate; it is not guaranteed by a successful build alone. Native online API calls explicitly use CapacitorHttp against the production HTTPS API; WebRTC and WebSocket voice connections remain online. No API key or server source is packaged. Native network requests have bounded timeouts; cancelling a JS wait does not necessarily cancel already-sent native HTTP traffic; never retry automatically.
Browser service worker caches a fixed public shell snapshot after the first successful online visit; a never-visited web URL cannot start offline. APIs, POSTs, audio, transcripts and personal data are not cached. Bump offline-assets.js version whenever a precached asset changes; do not activate incomplete caches. The old remote-only APK must be replaced by a bundled APK for reliable offline cold start. Future native UI changes require rebuilding the APK; no remote executable code update mechanism is introduced.
Offline: curriculum browsing, parent PIN and settings, progress reports, local picture/word review and existing deterministic writing/math activities work from bundled data. Local device speech voices may be used only if the OS declares them local; no reliable local voice is assumed. Audio-only English writing tasks block scoring until a voice is available. Cloud tutor, spoken assessment and cloud TTS require online connectivity. On loss of connectivity, the live session stops, the scoped plan remains saved, and an inline notice offers a retry (only a status request). Reconnection never starts the microphone automatically. Local review does not claim mastery. No cross-device sync is implemented.
Verification: automated transport/manifest/bundle tests and CI APK build; actual airplane-mode cold boot, same-signature upgrade, and live provider integration require emulator/device testing.
