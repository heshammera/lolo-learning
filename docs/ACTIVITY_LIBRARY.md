# Activity Library — admin authoring foundation
The approved owner-only web CMS will consume admin-src/activity-library.cjs. It inventories every registered or planned generic activity (7 implemented contracts, 22 planned), with stable IDs, Arabic labels, categories, runtime versions, offline support, evaluator/renderer, required configuration fields, example templates, and planned dependencies. Runtime readiness is derived from the actual activity-engine registry rather than administrator input. Planned types have no supported version or executable template. Legacy student speech/trace features do not imply generic contract support. Compatibility requires actual target capabilities; missing versions are incompatible. Library audit rejects omissions or template/schema drift.
Local visual prototype: run node scripts/preview-activity-library.js, then open the printed temporary HTML file. Search, filter by category/support/offline, view details and interact with the actual seven generic renderers. It uses no network or real data, has no publish controls, and is not a deployed admin application. Its source and generated UI are excluded from Android/offline student assets. Do not host it as a live CMS until server-side owner identity/RBAC/MFA and deployment isolation are implemented. The data-only catalog contains no private data.
