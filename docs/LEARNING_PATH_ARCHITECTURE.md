# Parent-controlled learning scope — verification milestone
The current version adds a device-local plan: one lesson, one unit, or a single curriculum program. Lesson order is taken from curriculum arrays; skipping previously completed legacy lessons is opt-in for multi-lesson plans. The parent PIN gates the selection. Changing the browsing selectors does not commit a new plan. A completed or invalid plan will not silently start another program. A restored plan never starts the microphone itself.
The engine stores ordered lesson IDs and an index; completion advances the stored index exactly once. A transition waits for the current reward and quiet audio, then closes the old provider connection and opens a fresh one with the remaining absolute time budget. If audio does not settle, the plan pauses instead. The child can stop manually. The voice tool cannot choose the next lesson.
Limits: local-only storage and PIN are not server authentication. Legacy live lesson correctness still depends on model grading; plan completion is not skill mastery. The current milestone does not implement central identity, authored question banks, full provider-independent scoring, unit quizzes, cross-device sync, or a complete continuous-audio verification on actual devices. Live provider calls must be explicitly authorized.
Tests: pure path engine tests cover lesson/unit/curriculum boundaries, order, opt-in skips, duplicate completion, corrupted data, and version mismatch. CI and live device checks are separate; do not label the feature verified until relevant checks pass.
