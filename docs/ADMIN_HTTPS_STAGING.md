# Isolated admin HTTPS staging (operator-only)
This is a deployable candidate, not an activated public service. Never expose port 4180; it remains bound to loopback. The student Vercel deployment and APK remain isolated. Use a dedicated admin DNS hostname and a trusted Debian/Linux server with Python, Node 22, Caddy and a separate PostgreSQL database. Only an approved operator IP/CIDR is permitted by the sample Caddy configuration; do not use a blanket allowlist. Do not put a CDN/proxy ahead of this IP matcher without redesigning the trust boundary.

1. Install dependencies in a virtual environment and configure the sample environment privately outside git, with a unique admin database DSN and persistent Fernet key. Generate a private proxy token using secrets.token_urlsafe(32). Use the same token in Caddy's private service environment, separate from the admin database secrets. Configure LOLO_ADMIN_DOMAIN and LOLO_ADMIN_ALLOWED_CIDR for Caddy; replace the example domain in the app environment. Do not commit keys, tokens or passwords.
2. From a trusted interactive operator terminal with admin environment configured, run `python admin-src/manage.py migrate`, then `python admin-src/manage.py provision --role owner`. Enroll a TOTP authenticator and wait for the next code before login.
3. Review/install the example systemd unit and Caddy config under admin-src/deploy. Run as dedicated unprivileged service user, ensure paths and Node executable are accessible, configure DNS and TLS, validate Caddy configuration, firewall 4180, and start services. Keep signing/export disabled until keys, review and delivery policy are ready.
4. Verify real HTTPS, disallowed network denial, login/logout and permission enforcement using synthetic data. The app requires an exact configured Host/Origin, overwritten HTTPS marker, private proxy header, Secure __Host- session cookies and shared PostgreSQL login quota. The old local mode remains explicit and separate.

Remaining launch blockers: external HTTPS integration and security review, ingress resource and per-source abuse controls, MFA recovery, key rotation, audit retention, DB backups/restore and live monitoring. Global login quota can be exhausted by an allowed operator, so do not enable anonymous Internet access. No domain, VPS access, database, certificates, owner account or production signing key is provisioned by this commit.
