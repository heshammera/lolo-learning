# Progress synchronization foundation (disabled, staging only)
Migration 002 adds a versioned child snapshot with a foreign key and cascading deletion. Parent authentication and child ownership are checked on every operation. Write requests require baseRevision and a UUID operationId; row locking serializes concurrent changes, stale revisions return HTTP 409, and an exact retry of the latest operation is idempotent. Older retries cannot overwrite newer revisions. A conflict requires an explicit read and resolution; no automatic merging or overwrite. Snapshot accepts only curriculum-versioned completion IDs and a validated scoped learning path. No free-form notes, speech, transcripts, names, or raw responses. Completed IDs are device-reported, not evidence of mastery. Full reports, skill events, writing results, local profile linkage, offline queue, UI and consent remain future work. Both LOLO_FAMILY_ENABLED and LOLO_PROGRESS_SYNC_ENABLED must be explicitly enabled; never enable for real families before privacy, verified consent, durable limits and review. Production DB not configured or migrated. Test on disposable PostgreSQL 16 with simultaneous conflicting writers and repeat operations.
