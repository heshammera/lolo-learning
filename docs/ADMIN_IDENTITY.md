# Isolated admin identity foundation
Separate admin database, migrations and operator CLI under admin-src. No public registration, no default owner, no admin HTTP routes, no production service or credentials provisioned. The operator must supply a separate DSN and encryption key via private environment; create the account in an interactive trusted terminal, enroll a TOTP authenticator and verify its code. Passwords use salted scrypt; MFA seeds encrypted with Fernet (key management/rotation still required), bearer token hashes stored in separate sessions. TOTP codes cannot be reused, account login failures lock known accounts for 15 minutes after five attempts, and successful login revokes prior sessions and expires in 30 minutes. Role permissions are explicit and evaluated from the database on every authorization. Audit rows record only actor/action/time. Parent tokens are not admin credentials.
Role policies: owner all current management capabilities; admin no owner/account management or billing/settings; content manager draft edit; teacher review; support limited support read. These permissions are policy contracts, not implemented CMS actions. No student API or APK integration. No HTTP auth surface yet; future admin deployment requires TLS, dedicated origin, secure cookies/CSRF, global and IP abuse controls, MFA recovery/rotation, audit retention and security review. Test in disposable PostgreSQL only. CLI: install admin-src/requirements.txt, configure LOLO_ADMIN_DATABASE_URL and LOLO_ADMIN_ENCRYPTION_KEY (Fernet key, securely generated and stored), run python admin-src/manage.py migrate then provision. Never paste real secrets into chat or logs. Identity tests cover TOTP, replay, role denial, expiry, revocation and durable lockout.

Student Vercel deployment excludes admin-src and the local admin preview generator via .vercelignore; the Android asset manifest remains an explicit allowlist. A future independent admin deployment must use its own build configuration. Additional DB tests verify role changes and disabled accounts take effect on existing sessions and audit records omit secrets.
