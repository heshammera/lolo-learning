# Visual CMS editor
The local-only admin UI now uses a data-backed visual editor instead of exposing JSON. It edits curriculum title, subject/grade identifiers, units, lesson titles/goals, ordered activities, and all seven implemented activity configuration types. Entries are cloned from the audited Activity Library with new stable IDs; planned types cannot be selected. Native controls edit options, correct answers, pairs, groups, order and numeric answers, with add/remove/reorder buttons. Preview uses the same student runtime, without writing results. A hidden serialization field preserves the existing server API. Server validation/revision enforcement remain authoritative. Unsaved changes prompt before switching drafts; teacher access is read-only. No release, publish, real curriculum delivery, media import, or full production UI yet. Browser CI uses synthetic/mock API, actual renderer and validator; separate PostgreSQL tests verify real server persistence/authorization. Subject and grade IDs are still text identifiers pending centralized taxonomy management.
