# Android signing and upgrades
The original CI debug APK uses an ephemeral runner debug key and versionCode 1. A build can succeed while an update fails because Android requires matching app ID and signer. The app ID remains com.heshammera.lolo and minSdk remains 24. The updated workflow uses its monotonically increasing run number for versionCode; reruns keep the same version. Debug APKs remain test-only and do not guarantee update continuity.

For a stable release, recover and inspect the original signing key first if existing installations must be upgraded in place. If unavailable, an intentionally new release signer requires a one-time migration/reinstall; do not uninstall until student progress has been backed up and restoration verified. Do not use a public or disposable debug signing key for distribution.

Trusted operator setup: generate or recover a long-lived release keystore privately (outside git); keep encrypted backups. Add repository Actions secrets LOLO_ANDROID_KEYSTORE_BASE64 (base64 of keystore), LOLO_ANDROID_STORE_PASSWORD, LOLO_ANDROID_KEY_ALIAS, LOLO_ANDROID_KEY_PASSWORD, and repository Actions variable LOLO_ANDROID_CERT_SHA256 (SHA-256 of the intended signer certificate, independently verified). Never share secrets in chat or commit them. Protect main and restrict workflow modification/access before adding release credentials. The signer pin is public information but must be independently controlled.

From Actions > Build Lolo Android APK > Run workflow, select main and signed_release. All existing tests run; an unsigned release is built and signing is first tested with a disposable key. Only the explicit main-branch run receives production signing secrets. The script verifies the signer, package, version, minimum SDK, alignment and non-debuggable status before emitting the signed artifact. A missing/mismatched key fails closed. Keep signed APK backups: CI artifacts expire. Do not distribute the disposable CI test APK.

Before commercial release, physically test installation, offline boot, same-signer upgrade preserving student progress, API access and microphone behavior. Actual existing-device failure has not been diagnosed without its Android error. This change does not create a real key or sign a production APK.
