# Opt-in curated content delivery (staging)
Student /api/content supports POST list and download by exact curriculum UUID and expected sequence; no admin DB/credentials/private keys, no dynamic URL or file path from client. Explicit LOLO_CONTENT_DELIVERY_ENABLED and an operator-controlled read-only catalog JSON file ({"format":1,"packages":[signed envelopes from approved-release export]}) required; max 12 packages / 4.5 MB. Operator must curate only content authorized for PUBLIC distribution. Catalog reader checks shape/size/encoding and rejects duplicates; it does not verify signature or editorial approval. Browser verifies pinned public key, package schema and exact signed catalog metadata before explicit parent confirmation/atomic install. Process-local rate limits, no-store API, no service-worker API cache. Native uses existing fixed HTTPS API transport. Empty production trust and disabled endpoint remain default. Catalog location/deployment, public-vs-paid entitlements, actual approved publisher workflow, key lifecycle, production monitoring and real-device verification are still open. No public release or deployment config was created. Tests use synthetic data; previous full offline E2E discovered hidden-button CSS bug, patched in 7b4258d, rerun pending.
