# Staging parent cloud UI
Three independent flags: LOLO_FAMILY_ENABLED, LOLO_PARENT_CLOUD_UI_ENABLED, LOLO_PROGRESS_SYNC_ENABLED. Keep all false for production; status advertises only enabled features. The protected parent settings panel supports login to an operator-provisioned account, listing and creating synthetic child profiles, explicit logout, and comparison of the active local profile with a selected remote child. Credentials and bearer token remain in memory, cleared when closing/locking the panel, moving to lessons, visibility loss or offline. Clearing the client is not guaranteed server revocation; explicit online logout revokes server session. No automatic requests that transfer progress. First backup requires a preview and explicit checkbox confirming synthetic data and correct profile mapping; existing remote revisions are never overwritten by the UI. No restore, persisted account link, offline queue or background sync yet. Local data stays untouched. Testing uses synthetic accounts/mock responses and no live AI requests. Real child data requires verified consent, privacy review, security review, durable quotas and a configured production database.

Chromium integration uses mocked same-origin API responses, verifies hidden-by-default panel, PIN gate, initial upload confirmation, no overwrite, no credential persistence and session clearing on panel close. This is a UI integration test, not a live production login or actual device verification.

Restore milestone: explicit confirmation creates a distinct local profile from a validated remote snapshot; original profile remains selected and untouched. Only completed lesson IDs and the curriculum-scoped path are restored, not skill mastery evidence, scores, voice or personal data. Staged namespace keys are written before publishing the registry; rollback is best-effort on write failure. Browser and storage tests exercise restoration and registry write failure. No automatic sync, merge, or persistent cloud association yet.

Approved first-backup queue: persist the exact limited snapshot and operation UUID before sending. No credential or bearer token in the queue. It is scoped to the local profile and checks the original parent, owned remote child, and unchanged local snapshot before explicit retry. An uncertain network failure retains the queue; a revision conflict blocks it; cancellation removes only local pending state, not a possibly committed remote backup. The parent must sign in again after disconnect and explicitly resume. This is not unattended synchronization or automatic multi-device updates. The browser test simulates a lost response after the server accepted a write, reload, re-login, and retry with the same operation UUID.
