# Voice service safety milestone
Adds per-process aggregate admission control across paid routes, combined per-client TTS limit, explicit voice/TTS/provider kill switches, cross-site browser rejection, strict JSON constants/body length, and malformed onboarding input validation. Defaults preserve existing enabled services. These controls are NOT authentication, actual spend accounting, or a shared quota across Vercel instances; client IP limits are not reliable identities. Counts include invalid requests and cache hits. Operators can disable services using server environment settings, but existing issued provider credentials are not revoked by this mechanism.
Client stops interrupted live sessions and retains completed lessons/plan position. WebRTC transient disconnect is given five seconds before pausing; Gemini goAway pauses immediately. No automatic microphone reconnect on failures; startup provider fallback stops for access-denied, throttled or known offline conditions. Unfinished question progress may need to be repeated. Provider behavior and mobile audio are not verified on real services/devices. Tests use mocks; no paid calls.
Next: central identity/authorization, durable shared quota, provider policy eligibility and consent, short-lived constrained credentials verified against current provider API, privacy review, comprehensive transport tests. Do not claim child safety or production security certification.
