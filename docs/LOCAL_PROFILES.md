# Local child learning profiles
Parent PIN gates the new management UI. Add up to 12 local profiles including the original, rename using a nickname and switch by reloading the application. All existing data remains in the original default namespace; new profiles start empty. The active profile is pinned per document so delayed callbacks cannot write into a newly selected profile. Shared device PIN remains global. Learning settings, path, mastery/completion, visual and writing results, skill progress, onboarding and curriculum selections are scoped by the explicit key allowlist in storage.js. Any future child-specific storage key must be added to that allowlist. Corrupt registry blocks scoped writes rather than overwriting previous data. Cross-tab selection change triggers reload; concurrent tabs for the same profile still have last-writer-wins limitations. Local profiles are not server accounts or a security boundary against device owners. No cloud migration or sync; no deletion of profiles yet. Parent reset/clear acts on the currently open profile. Test offline creation/switch/return and original data retention in Chromium and storage unit tests. Native device checks remain pending.
