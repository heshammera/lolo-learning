# Family identity foundation (disabled by default)
PostgreSQL schema: parent accounts, hashed opaque session tokens, minimal child profiles, owner foreign keys, expiration and revocation. Passwords are salted scrypt hashes; no plaintext passwords or bearer tokens stored in DB. Explicit migration and operator provisioning via scripts/family_admin.py. No public registration, password reset, email delivery, or identity/parental-consent verification. Nicknames and coarse age bands only; no names, birth dates, audio, transcripts, or school details requested. Do not enter real child data before privacy/consent review.
The opt-in POST /api/family endpoint supports login, listing/creating/deleting owned child profiles, logout. It is disabled unless LOLO_FAMILY_ENABLED is set to true. This milestone does not add a user-facing login screen, protect existing voice routes with account auth, migrate device progress, or implement cross-device sync. Existing offline device mode is unchanged. Process-local login throttling is preliminary; a durable account/IP rate limit and session lifecycle policy are required before public enablement.
For a dedicated staging database only: install requirements.txt; set LOLO_DATABASE_URL privately (require TLS for remote DB); run python scripts/family_admin.py migrate, then provision. Keep the production feature disabled until a reviewed identity/consent flow, security review and protected UI are implemented. A separate CI workflow provisions an ephemeral PostgreSQL 16 service to test password verification, ownership, token revocation, expiration and isolation. Never point LOLO_TEST_DATABASE_URL at production. Production database not provisioned or migrated by this change.

Additional integration tests exercise the actual HTTP handler on a disposable local server, authorization headers, no-store responses, cross-account deletion rejection, disabled parents and logout.

Hosted synthetic pilot candidate: hosted family endpoints fail closed unless explicitly configured with synthetic mode, a distinct pilot DSN, a distinct-from-primary budget DSN and required shared login admission. Test accounts must end @example.test and newly created profiles use Synthetic plus digits. No production user registration or real consent. The operator must independently confirm the credentials identify genuinely separate databases (different DSN strings alone do not establish isolation), apply reviewed migrations only to the pilot, provision fixture accounts and review existing records before enabling. No deployment variables changed. CI pending.
