# Independent administration deployment preflight
Run from the dedicated server with the private administration environment: `python admin-src/preflight.py`. The example systemd unit runs it before startup. It validates HTTPS mode, exact origin/token, private port, separate DSN, initial flags off, encrypted remote connection with verify-full, admin schema, SELECT privileges, presence of an enabled owner, and successful Activity Library generation. A catalog inspection also rejects known family/billing tables in any schema, including when distinct DSN strings refer to the same mixed database. Only reads the explicitly configured admin database, with statement timeout and read-only transaction. No account identities, keys, DSNs or exception details logged.
This is an additional preflight, not a complete security audit or deployment. The operator must confirm the actual database identity, grant required write/sequence privileges, configure TLS and IP allowlist, test HTTPS ingress and backups, and provision MFA in a private terminal. Local socket or loopback DB is permitted; remote DB requires verified TLS and a trusted CA. No real server, domain, migration or owner enrollment performed. CI uses disposable DB only. For initial HTTPS keep billing, family pilot management and signing/export disabled.
