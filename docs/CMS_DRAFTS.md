# CMS draft foundation
Separate admin DB migration 002; authenticated curriculum:read listing and retrieval, curriculum:edit validation and save. Each draft has revision, stable UUID, author/updater, timestamps. Strict bounded subject/grade/unit/lesson/activity structure. Server invokes the same trusted JS activity validator (bounded JSON, subprocess time/concurrency) before saving; unsupported types/versions, duplicate IDs, invalid answers fail closed. Atomic revision comparison prevents silent overwrites. No execution of authored code. UI is a first JSON editor/template, not the final visual builder. Drafts are not integrated with learner curriculum.json or progress, no public delivery or publish route. The current server only binds loopback. Review workflow, immutable releases, rollback, full visual editing and capability manifests for deployed APKs remain to be implemented. Validation describes current engine, not installed client versions. Production admin database not migrated.
