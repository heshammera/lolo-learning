# Separate admin web — local staging
Run only on a trusted operator machine. The service binds to 127.0.0.1, requires LOLO_ADMIN_LOCAL_WEB=true, a separate admin database, encryption key and provisioned TOTP account. Install admin-src/requirements.txt and Node 22; run python admin-src/manage.py migrate/provision first; then python admin-src/admin_web.py and open the printed 127.0.0.1 origin. Do not use real child data. The site is separate from the student Vercel deployment and APK. It has no public deployment, publishing, or CMS editing yet.
Admin login uses a same-origin JSON POST with exact Host/Origin validation, a bounded global process-local login rate and concurrent hash cap, short DB sessions via HttpOnly SameSite=Strict loopback cookie, no bearer tokens in JS, no-store responses, CSP, no framing, explicit logout and DB authorization for the library and shared renderer on every request. Role changes are enforced server-side. UI lists actual catalog, search/filter/preview, and session polling. HTTP tests run with disposable PostgreSQL and verify authorization, CSRF/origin, session revocation, headers and login limit. Browser rendering is not yet independently verified.
This is loopback HTTP only, not a production server. Before public launch: dedicated HTTPS deployment, Secure __Host- cookie, distributed throttling, reverse-proxy configuration and security review, MFA recovery and encryption key lifecycle, independent browser/mobile tests. Never expose the current HTTP listener via a public reverse proxy.

The loopback cookie is not Secure and cookie isolation is by hostname, not port; use a dedicated local browser profile, avoid running other untrusted services on the same hostname, and never treat the local listener as production-ready. Library previews re-check the current library permission and clear old content on refresh.
